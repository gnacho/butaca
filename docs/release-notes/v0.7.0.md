# v0.7.0 - Jellyfin artwork, subtitles and audio tracks

This release fixes the Jellyfin backend's pictures and its tracks: the app now loads an item's backdrop, poster and logotype, brings up the default subtitle on its own, and can switch to an audio track the television cannot decode directly instead of leaving the previous one playing. It is the first Butaca release cut from this repository rather than from upstream, and the first whose package identity matches the app it installs.

## Fixed

- **Item artwork loads again.** Backdrops and posters were requested with a malformed address, so the server answered 400 and the tiles stayed skeletons. Home and the detail pages now show the picture the server holds.
- **The hero logotype is asked for correctly.** It was requested from a Plex-shaped path that Jellyfin does not serve, so it answered 404 and the hero fell back to plain title text. It now uses the item's own logo image.
- **The default subtitle comes up with the film.** Direct play now honours the file's default subtitle, the way the Plex backend already honoured a subtitle chosen on another client. Before this, every Jellyfin play started with subtitles off.
- **Changing to an audio track the television cannot decode directly now works.** Picking a DTS or TrueHD track asks the server to re-encode with that track selected. Previously the pick was silently ignored and the previous track kept playing.

## Compatibility

- **Starts, and nothing further is known - every firmware from webOS 4.0 up.** The loader boundary is unchanged from plx-native v0.6.5, which this release is built on. Static evidence says the process starts; it says nothing about whether a picture appears.
- **Does not start - webOS 3.9.2 and older.** Symbols the app needs are missing from those firmwares, so the process is killed before anything appears.
- **The changes in this release are simulator-verified, not television-verified.** The artwork, the default subtitle and the audio switch were exercised against a real Jellyfin 12 server in the desktop simulator. No television has run them yet.

## Known issues

- **The audio re-encode has not run on a television.** Its request is unit-tested and the surrounding code runs in the simulator, but no television has played a track switched this way. It is the one item this release most needs a report on.
- **A subtitle that needs the server to burn it in stays off.** That matches the Plex backend, which deliberately does not pay the re-encode cost for a burn. A bitmap (PGS) or sidecar subtitle will not appear on a Jellyfin transcode.
- Every known issue in [the plx-native v0.6.5 audit](https://github.com/GLinnik21/plx-native/blob/main/docs/release-audits/v0.6.5.md) that this fork inherits remains unless superseded above.

## Help test this release

If you use Butaca against a Jellyfin server, the audio-track switch is the one thing nobody here can confirm without a television. Pick a film whose target-language track is DTS (for example WALL-E, whose Spanish track is DTS) and switch to it: the audio should change after a short re-buffer. Tell us what happened in [issue #10](https://github.com/gnacho/butaca/issues/10). A report that it worked is as useful as one that it did not.

## Installing

Download **com.butaca_0.7.0_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.butaca_0.7.0_arm.ipk
```

[Installing and checking a download](https://github.com/gnacho/butaca/blob/main/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.7.0](https://github.com/gnacho/butaca/blob/main/docs/release-audits/v0.7.0.md).
