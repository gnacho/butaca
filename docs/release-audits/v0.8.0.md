# Release audit - v0.8.0

The evidence behind [the v0.8.0 release note](https://github.com/gnacho/butaca/blob/main/docs/release-notes/v0.8.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

v0.8.0 is the first installable package published from this repository. v0.6.5 announced the client and carried no `.ipk`, and the tags after it were pushed without a release, so no 0.7 build ever reached a user. The package is a different product from the 0.6 line in one respect that matters to a reviewer: it speaks to a Jellyfin server only. The Plex client, its sign-in, its profile handling and its code paths are not in this tree.

## Known issues at release, with provenance

- **Video on some 2019 k5lp/k3lp sets installed through Developer Mode** (#74). LG's sandbox can withhold `/dev/rtkmem`, the app detects it and refuses to load instead of crashing, and the failure screen offers Repair on a rooted set. Measured on a k5lp set by the reporter of #74; not re-measured on this build, which has no such set here.
- **A transfer that stops short is retried rather than reported as the end of the film** (#74, #87). The retry reopens the stream at the byte it reached, up to four times. It is host-tested; no television has run the fixed path against a real truncated transfer yet, so the note offers it as a fix and this audit records that the device half is missing.
- **2018 sets on firmware reporting platform release 3.9.3** sign in and browse but have never been seen to start video, with no error reported. Pre-existing, carried from the README, unsolved here.
- **A crash on sets built on LG's k6hp chip** (#174). Seen only in reports from owners; not reproduced, because no such set is available. Unchanged by this release.
- **Playback on webOS 5 and newer is unreported on this version.** The app starts there per the static matrix; the interface and player chrome changed in this release and nobody has watched a video on those sets since.
- **The plain-HTTP exception is limited to a local address literal.** A server reached by name needs `https://`. Sign-in refuses to send a password over plain HTTP to anything it cannot prove is on the local network. A design decision rather than a defect, recorded because a reviewer will ask.

## Deliberately not done

- **No device run for this release.** The maintainer's television was not used. Every claim that needs glass is therefore either carried from an older build with its date, or asked for in the note.
- **No Plex import.** The Plex watch history and profile list belong to the server, and the client that read them is gone; there is nothing local to convert.
- **No downgrade path.** A 0.6 build reading the file this version writes would find a token where it expects a password and ask for the password; the note does not promise otherwise.
- **No GitHub Security Advisory** for the 0.6 line's password-at-rest file. It is a design change disclosed in the note with its residual, not a defect in a release that carried an installable package, and no 0.6 package was ever published from this repository.
- **No firmware claim beyond startup** for 5 and newer. The matrix grades the loader.

## Release configuration

| | |
|---|---|
| flavour | `com.butaca` (stable) - the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged, Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

What is unusual about this build, relative to the 0.6 line:

- **The bundled engine is named for this app.** The FFmpeg libraries and the subtitle renderer ship as `libav*-butaca` and `libass-butaca`, opened by absolute path from the app's own directory, so they can neither shadow nor be shadowed by the television's own copies.
- **A subtitle renderer is bundled.** `libass-butaca.so.0` links FreeType, FriBidi and HarfBuzz statically, so a firmware's own copies cannot take over styling. This is what makes ASS and SSA render with their styles during direct play.
- **The storage helper is `com.butaca.storage`**, a separate LS2 service in the package, and the diagnostics it publishes are the one file a Developer Mode shell can read beside the app's logs.
- **No crash reporter is shipped.** The capture library the Plex line carried is not in this tree, and the payload carries no `sentry-crash` binary.
- **The licence is GPL-3.0-or-later**, and the release attaches the program's own corresponding-source archive beside the FFmpeg tarball and its build script.
