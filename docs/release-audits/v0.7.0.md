# Release audit - v0.7.0

The evidence behind [the v0.7.0 release note](https://github.com/gnacho/butaca/blob/main/docs/release-notes/v0.7.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written before the release ran.

## What this release contains

- **Artwork on the Jellyfin backend.** The image request builder appended its sizing query with `&` to paths that carry no query of their own, so the backdrop path and any poster without a cache tag came out malformed and the server answered 400. The separator now follows the path. Verified against the live server (400 before, 200 after) and in the simulator: the old binary logged eleven failed image requests on Home, the new one none, and the capture grew from 477 KB to 2.86 MB.
- **The hero logotype path.** It was built as a Plex path for every backend, so Jellyfin answered 404 and the hero drew title text. It now uses the item's own logo image on Jellyfin and keeps the Plex shape.
- **The default subtitle read-back.** The Jellyfin direct-play plan started with subtitles off and never consulted the server. It now honours the file's default subtitle, the equivalent of the Plex arm's per-part selection, which Jellyfin does not carry. Simulator-verified: `ff: sub tracks=[...] selected=0` where it used to read `-1`.
- **The audio re-transcode arm.** A switch to a track whose codec is not direct-playable resolved its client from the Plex registry, where the Jellyfin slot is not registered, so the intent was rejected and nothing happened. `retranscode_for` now has a Jellyfin arm that POSTs `PlaybackInfo` with `MediaSourceId` and `AudioStreamIndex` in the body and installs the returned HLS route. Probed against the live server: the indices are honoured only when `MediaSourceId` rides the body, so both fields are asserted in a unit test.
- **Package identity.** The tracked `ipkroot/ctl/control` still named the upstream package, which failed the release workflow's tag/version gate before any build ran. It now names this fork's stable id, and the release tooling derives that id rather than hardcoding it.

## External compatibility reports known at release time

None for this fork's changes. The compatibility evidence this release inherits is the upstream project's, recorded in [the plx-native v0.6.5 audit](https://github.com/GLinnik21/plx-native/blob/main/docs/release-audits/v0.6.5.md).

## Compatibility tiers, and what moved

No firmware moves to a broader tier. The loader boundary is unchanged from the base this fork is built on, and the changes in this release are simulator-verified, so they add no television evidence and promote no tier.

## Known issues at release, with provenance

- **The audio re-encode has not run on a television.** The request builder is unit-tested and the code path is reachable in the simulator, but the simulator's engine does not reach the state that consumes the switch intent, so the end-to-end switch is unverified. This is the release's main open item.
- **The subtitle burn is deliberately not implemented.** Selecting a bitmap or sidecar subtitle on a Jellyfin transcode does nothing, by parity with the Plex arm, which does not pay the re-encode cost for a burn.
- Every known issue in the upstream v0.6.5 audit not superseded here remains.

## Release configuration

| | |
|---|---|
| flavour | `com.butaca` (stable) - the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |

| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK and Rust nightly pinned by the release workflow; final values are generated from the release run |

This release adds no bundled dependency, no new outbound host, and no new file the app writes outside its existing directories.
